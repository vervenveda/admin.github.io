# Khaemenes Brood — Shadow-Mode Commissioning

This directory stages Academy/learning QA observations for convergence through the existing Araneae/MAVRIC human-review architecture.

## Authority boundary

The brood is observational. It may observe, compare, correlate, explain, and recommend. It may not modify repositories, alter grades, expose protected answer bodies, collect learner records, or perform autonomous consequential actions. Human review remains final authority.

## Trial Set A

`trial-set-a.json` defines the first public/non-sensitive proving set:

1. `vervenveda/arcade.github.io/Checkers_Variant_Lab_index.html` — complex state, rules, local learning, runtime and accessibility.
2. `vervenveda/arcade.github.io/AffixSix™_index.html` — AI timing, local persistence, schema migration, runtime and accessibility.
3. Geometry Units 01–03 in `vervenveda/Khaemenes_High.github.io` on `draft/geometry-a-plus-plus-first-pass` — curriculum structure, assessment contracts, mastery evidence, standards, navigation and validator evidence.

## Observation shape

Trial observations intentionally use the same admin-safe field vocabulary already established by the Beta Brood report contract: `eventId`, `spyderClass`, `observedAt`, `target`, `category`, `severity`, `observed`, optional comparison/inference/recommendation/confidence/digest fields, and `authority: human-review-required`.

This keeps Trial Set A compatible with the existing convergence philosophy without pretending that Khaemenes educational QA is the Beta Brood.

## Commissioning rule

Run in shadow/read-only mode first. Compare brood findings against independent human/MAVRIC forensic review. False positives, false negatives, privacy boundary violations, category confusion, or evidence-lineage loss are commissioning defects and should be repaired before expanding the brood to additional Academy repositories.
